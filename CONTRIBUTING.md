# Contributing — draft policy

This is a proposed workflow, not an approved `storytold` contribution rule.

- Open an issue or discussion for a new cross-app capability; link existing related issues to prevent duplicate implementations.
- Keep PRs focused, branch from `main`, include scope, security considerations, tests performed, migration impact and docs changes. Favor review via PR (matching `craft-ai-integrations` pattern) rather than direct pushes.
- Suggested commit format: `feat(storage): add immutable blob verification`, `fix(auth): revoke sessions on password reset`, `docs: document integration contract`.
- Do not add images, logos, fonts or copy upstream code with unclear reuse terms. For original assets keep attribution records.
- Every new domain behavior: unit tests, negative authorization tests, malformed payload tests and an operational failure scenario.
- No production changes without lint, format, test and migration verification once these checks exist. Required CI rules will be established in Phase 0/1.
- No autogenerated claims of security, performance, or production readiness without corresponding test evidence.

See `docs/01-repository/governance-and-ci.md`, `docs/08-quality/verification-matrix.md` and `docs/10-community/github-rfc-en.md`.
